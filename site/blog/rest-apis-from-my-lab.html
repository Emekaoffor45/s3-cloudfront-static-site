The APIs from my week 2 lab, checked against the REST lecture

In the week 2 lab for COM769 (Scalable Advanced Software Solutions, part of my MSc at Ulster) we called a few public APIs from Postman: the Stack Exchange API, PokéAPI and a Yoda translator. The lecture that week was about what makes an API properly RESTful. I didn't connect the two at the time, so I went back to the lab APIs with the lecture slides open next to them.

The slide that matters most here is the Richardson Maturity Model. Level 0 is one URI with every operation sent as a POST. Level 1 gives each resource its own URI. Level 2 uses the HTTP verbs properly. Level 3 adds hypermedia, meaning the response itself contains the links you need to find related resources, so the client doesn't have to know how the URLs are built. The lecture says most published APIs sit around Level 2, and that Level 3 is what Roy Fielding actually meant by REST. Fielding made the same complaint himself in a 2008 blog post titled "REST APIs must be hypertext-driven".

PokéAPI

The lab starts with:

GET https://pokeapi.co/api/v2/pokemon/squirtle/

Then for the next request you scroll through the response, copy the URL of one of Squirtle's abilities and send that. During the lab it felt like a Postman exercise. Looking at it again, it's the Level 3 idea in practice. You never work out what an ability URL looks like, because the response gives it to you: 

"ability": {
  "name": "rain-dish",
  "url": "https://pokeapi.co/api/v2/ability/44/"
}

I counted how many times the full Squirtle response links to other PokéAPI resources. It's 2,642.

The response is also about 309 KB, for one Pokémon. Most of that is move data for every game version, which you didn't ask for if all you wanted was Squirtle's abilities. The lecture covers this trade-off from both ends. Avoid "chatty" APIs that need lots of small requests to get anything done, but don't go so far the other way that every response drags along data the client won't use. PokéAPI is at the "send everything" end. In fairness, its documentation asks you to cache responses locally, and the response headers say it can be cached for a day (Cache-Control: public, max-age=86400).

So is it Level 3? Not completely. The lecture's definition of HATEOAS also expects the response to say which operations are available on each linked resource, and PokéAPI only gives links. It's also read-only. The docs call it "consumption-only". I sent it a POST to see what would happen and got 403 Forbidden. The status code table in our lab suggests 405 Method Not Allowed for that situation, so real APIs don't always return the code you'd expect from the textbook.

Stack Exchange API

The first request in the lab is:

GET https://api.stackexchange.com/2.3/questions?order=desc&sort=activity&site=stackoverflow

The /2.3/ in the path is URI versioning, which is the first of the three versioning approaches in the lecture (the others are a query string and a custom header). The results come back inside a wrapper object with four fields: items, has_more, quota_max and quota_remaining. Each question has a link field, but it points to the page on stackoverflow.com, not to anything in the API. So I'd put it at a solid Level 2. The resources and verbs are done properly, but there's no hypermedia.

What I missed during the lab was quota_max. Without an API key, mine was 300. The throttle documentation says that when an app has no access token, the quota is shared by every application on the same IP address. If a whole lab room goes out to the internet through one public IP, that's 300 requests a day between everyone in it, and the optional Python part of the lab uses one up every time you run the script.

The Yoda translator

I couldn't test this one again. My requests were stopped by a Cloudflare check before they reached the API. Two things from its documentation are worth knowing, though. The docs now show the endpoint as /translate/yodish, while the lab uses /translate/yoda, so if the lab request fails for you, that could be why. And the URL has a verb in it, "translate", which goes against the lecture's advice to name URIs after nouns. The same lecture does allow POST for operations that don't create anything, and translating a sentence is a fair example of that.
